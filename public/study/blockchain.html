Module 1 · Introduction to Blockchain Platforms

What a blockchain is

1.1Definition & core properties★ high yield

BlockchainA decentralised, distributed, immutable digital ledger of records (blocks) securely linked by cryptographic hashes.
PropertyMeaning
DecentralisationNo central trusted authority; consensus keeps nodes consistent
Persistency / immutabilityOnce in the chain, a block is effectively impossible to alter or roll back
AnonymityUsers act through addresses, not real identities
AuditabilityEvery transaction references earlier ones, so all activity is verifiable
Extra marksHistory for a mark or two: David Chaum (1982) proposed the earliest blockchain-like protocol; Haber & Stornetta (1991) built cryptographically chained timestamps; Satoshi Nakamoto (2008) added proof-of-work to solve double-spending.

1.2Anatomy of a block★ high yieldpast paper

A block = an 80-byte header + a transaction counter + the body of transactions.

Consensus & the trilemma

1.3Proof of Work — and Byzantine fault tolerance★ high yieldpast paper

PoW loop: a miner builds a candidate block → hashes Prev Hash + Merkle Root + Nonce → checks if hash ≤ difficulty target → if not, change the nonce and repeat (trillions of times) → if yes, broadcast; other nodes verify and append.

Byzantine Generals ProblemHow can distributed parties agree when some may be faulty or malicious? Consensus is the solution — PoW makes cheating economically pointless. PBFT (Practical Byzantine Fault Tolerance) tolerates up to ⌊(n−1)/3⌋ faulty nodes and is used by permissioned chains like Hyperledger. + added
Exam trapThe decks never define the Byzantine Generals Problem or PBFT, but they’re Q6 on the past paper (5 marks). Added here.

1.4The blockchain trilemma

TrilemmaA base-layer blockchain can maximise only two of three: Security · Decentralisation · Scalability.

Bitcoin optimises security + decentralisation, sacrificing scalability (≈7 TPS). Fixes: Layer 1 — PoW→PoS, sharding; Layer 2 — rollups, state channels, sidechains.

Extra marksEnergy angle worth a line: pre-Merge Ethereum ≈ 55 TWh/yr; Bitcoin ≈ 135 TWh/yr, ~1777 kWh per transaction versus Visa’s 0.0015 kWh. Ethereum’s move to PoS cut its energy ~99.95%.

Module 2 · Ethereum

Ethereum basics

2.1The world computer★ high yield

EthereumA global, open-source platform for decentralised applications — a distributed state machine (“world computer”) whose state is a set of accounts and whose transitions are transactions, executed by the Ethereum Virtual Machine (EVM).

Bitcoin is a distributed ledger (mostly currency); Ethereum is a distributed state machine running arbitrary programs. Its contract language is Turing-complete — it supports loops and unbounded computation, unlike Bitcoin’s deliberately limited Script.

Exam trapVerification challenge: because the language is Turing-complete, you cannot prove in advance that a contract halts (the Halting Problem). Ethereum’s answer is gas metering — every operation costs gas, and execution stops when the gas limit is hit. This is the exam’s favourite “why does Ethereum need gas” point.

2.2Consensus: PoW or PoS?★ high yield

Exam trapYour material is mixed. The 99-slide deck teaches Ethereum as Proof of Work (pre-2022 — miners, gasPrice, difficulty bomb). The modern 15-slide deck teaches Proof of Stake (post-Merge — validators, EIP-1559 fees). The real, current answer is Proof of Stake (The Merge, Sept 2022). If a question is rooted in the mining/difficulty narrative, it’s implicitly PoW; if it asks “what does Ethereum use today”, say PoS.

PoS: validators stake ETH and are chosen to propose/attest blocks; misbehaviour is “slashed”. Separates an execution client from a consensus client. Cut Ethereum’s energy use by ~99.95%.

Accounts, keys & wallets

2.3EOA vs contract account★ high yield

Externally Owned Account (EOA)Contract Account
Controlled byA private keyIts own code
Can initiate a tx?Yes (signs transactions)No — only reacts to being called
Has code?NoYes

An address is 20 bytes, derived from the public key, which is derived from the private key. Ethereum uses the account/balance model with a per-account nonce — contrast Bitcoin’s UTXO model. The nonce (count of txs sent) prevents replay.

2.4Wallets & keys

A wallet is a keychain, not a store of ether — the ether lives on-chain; the wallet holds the keys that control it.

  • Non-deterministic (JBOK) — “just a bunch of keys”, each random and unrelated. Hard to back up; discouraged.
  • Deterministic (HD) wallet — all keys derived from one seed in a tree (BIP-32). One backup recovers everything.
  • Mnemonic seed (BIP-39) — the seed encoded as 12/24 words (MetaMask). The only way to restore the wallet; keep it offline.

Mist = the historical official full-node GUI wallet. MetaMask = the lightweight browser-extension wallet talking to a node over JSON-RPC.

Transactions, gas & the EVM

2.5Transaction structure★ high yieldpast paper

TransactionA signed message from an EOA, transmitted by the network and recorded on-chain. It is the only thing that changes state or triggers contract code — contracts never run on their own.
FieldMeaning
NonceCount of txs from this account (prevents replay)
Gas priceWei the sender pays per unit of gas
Gas limitMax gas the sender will buy for this tx
Recipient (to)20-byte destination address (EOA or contract)
ValueEther to send
DataPayload — contract call / creation bytecode
v, r, sThe ECDSA signature components (no explicit “from” — it’s recovered from these)

Serialised with RLP (Recursive Length Prefix) encoding. The four value/data combinations: value only = payment; data only = invocation; both = payment + invocation; neither = empty tx.

2.6Gas★ high yield

GasThe fuel of Ethereum — a separate unit from ether that meters computation. Every EVM opcode costs gas; you pay gas used × gas price in ether.

Gas limit caps the work a tx can do, so an infinite loop drains only the limit, not your whole balance. Unused gas is refunded. Higher gas price → faster confirmation. Post-EIP-1559 the fee splits into maxFeePerGas and maxPriorityFeePerGas (a base fee is burned + a tip to the validator).

Extra marksTie gas back to Turing-completeness (card 2.1): gas is the economic substitute for formal verification — you can’t prove a contract halts, so you meter and bound it at runtime instead. Making that link is a distinction-level point.

2.7The EVM & Soliditypast paper

The EVM is a stack-based, Turing-complete virtual machine that every node runs identically; Solidity compiles to EVM bytecode. It’s Q10a on the past paper (“EVM with labelled diagram”) — sketch: transaction → EVM (stack + memory + storage, reads world state) → updated state.

pragma solidity ^0.8.0;

contract SimpleStorage {
    uint256 storedData;

    function set(uint256 x) public {
        storedData = x;
    }
    function get() public view returns (uint256) {
        return storedData;
    }
}

Web3.js is the JS library that talks to a node over JSON-RPC (eth_sendTransaction, eth_getBalance) — the front-end path. A Java app uses Web3j and explicit RPC calls instead (Q10b: Java-RPC vs JavaScript native).

Extra marksERC-20 is the fungible-token standard (functions transfer, approve, balanceOf). Naming it, plus ERC-721 for NFTs, adds easy marks to any “tokens / standards” question.

Clients, testnets & worked examples

2.8Clients & testnets

Geth (“Go Ethereum”) is the reference client. Historic testnets and their consensus: Ropsten = PoW; Kovan and Rinkeby = Proof of Authority (ether requested, not mined). Test ether comes from faucets and has no value.

Testnet vs local chain: a testnet is a live public chain with other users (realistic, slower to sync); a local chain (e.g. Ganache) is instant and private but behaves nothing like the real network.
