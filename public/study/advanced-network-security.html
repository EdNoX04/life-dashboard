Module 1 · VPN & Wireless IoT Security

Firewalls

1.1What a firewall is★ high yield

Firewall

A network security device that monitors and filters incoming and outgoing traffic against a set of pre-established security rules. It sits as a barrier between a trusted network and an untrusted one (e.g. your LAN and the internet).

TypeLayer / how it worksTrade-off
Packet-filtering (stateless)Inspects each packet alone by IP, port, protocol (ACLs). Layer 3–4.Cheap, fast; no context, easily fooled
Stateful inspectionTracks connection state, allows replies to known sessions. Layer 3–4.Better security, moderate cost
Proxy / applicationIntermediary; inspects content at Layer 7 before forwarding.High security; slow, expensive
Next-Gen (NGFW)Adds deep packet inspection, app-awareness, IPS, threat intel, AI/ML.Comprehensive; high cost/complexity
Circuit-level gateway + addedVerifies TCP handshake at Layer 5 (session); does not inspect payload.Low overhead; no content check
WAF (Web App Firewall) + addedLayer-7 filter specifically for HTTP/S — blocks SQLi, XSS, CSRF.Protects web apps; web-only

Advantages: prevents unauthorised access, monitors traffic, customisable rules. Limits: cannot detect internal/insider threats, may slow the network, needs regular rule updates.

Extra marksThe decks only list the first four types. Naming the circuit-level gateway and the WAF, and giving the OSI layer each one operates at, is the difference between a full-marks taxonomy answer and a half one.

IDS & IPS

1.2Detection vs prevention★ high yieldpast paper

IDSIntrusion Detection System — monitors traffic and alerts an administrator. Passive; it watches, it does not block.
IPSIntrusion Prevention System — detects and blocks threats in real time. Inline; often built into an NGFW.
FeatureIDSIPS
ActionDetects onlyDetects & prevents
PlacementPassive (out-of-band)Inline (in the traffic path)
ResponseRaises alertsBlocks / modifies traffic
ImpactNo added latencyMay add latency

Network-based (NIDS/NIPS) watches a whole subnet at a gateway — broad view, low host impact, but can miss encrypted traffic. Tools: Snort, Suricata, Cisco IPS. Host-based (HIDS/HIPS) runs on one machine watching file changes and system calls — catches insider threats and sees inside encryption, but is resource-heavy per host. Tools: OSSEC, Tripwire.

Likely question“Differentiate between network-based and host-based IDS/IPS with examples.” (both CSE337 papers) — answer with the placement/visibility/encrypted-traffic trade-off above, one tool each.

1.3Signature vs anomaly detection★ high yieldpast paper

CriteriaSignature-basedAnomaly-based
DetectsKnown threats onlyKnown + unknown (zero-day)
AccuracyLow false positivesHigher false positives
ResourcesLightweightComputationally heavy (ML)
UpdatesFrequent signature DB updatesInitial baseline training only
Best forAntivirus, Snort rulesFraud detection, IoT anomalies

Signature matching works like antivirus — fast pattern lookup against a threat database, but blind to zero-days and polymorphic malware. Anomaly detection builds an ML baseline of “normal” and flags deviations — catches the unknown at the cost of false alarms.

Likely question“Compare signature- and anomaly-based detection… which would you recommend for a modern enterprise?” (Sept-2025 mid-sem). Recommend a hybrid: signature for cheap known-threat coverage, anomaly layered on for zero-days.

1.5Inside IPSec — the deck skips this, examiners don’t+ added★ high yield

Two protocols inside IPSec:

  • AH (Authentication Header) — integrity + authentication only, no encryption. Protocol number 51.
  • ESP (Encapsulating Security Payload) — integrity + authentication and confidentiality (encryption). Protocol number 50. This is the one actually used in VPNs.

Two modes: Transport mode encrypts only the payload and keeps the original IP header (host-to-host). Tunnel mode encrypts the entire original packet and adds a new header (gateway-to-gateway — this is what a site-to-site VPN uses).

IKE (Internet Key Exchange) negotiates the keys over UDP 500 (and UDP 4500 for NAT traversal): Phase 1 sets up a secure channel between peers (Main or Aggressive mode); Phase 2 negotiates the actual IPSec SAs (Security Associations) for the traffic.

Extra marks“Describe the VPN architecture and the working of IPSec and SSL/TLS” is Q4 on the Feb-2026 paper (10 marks). The deck gives you SSL/TLS and the VPN types but nothing on AH/ESP, tunnel/transport or IKE — this card is where those 4–5 marks live.

Wireless security: WEP → WPA3

1.6The four generations★ high yieldpast paper

StandardCipherKey mgmtIntegrity
WEPRC4, 24-bit IVNoneCRC-32 (broken)
WPARC4 + TKIP, 48-bit IV4-way handshakeMichael (MIC)
WPA2AES-CCMP4-way handshakeCBC-MAC
WPA3AES-GCMP-256SAE + ECDH/ECDSABIP-GMAC-256

WEP — RC4 stream cipher with a tiny 24-bit IV; cracked in minutes. WPA — a stopgap that bolted TKIP onto RC4. WPA2 (802.11i) — mandates CCMP, an AES mode; still the common baseline. WPA3 — replaces the pre-shared-key handshake with SAE (Simultaneous Authentication of Equals, “Dragonfly”), which resists offline dictionary attacks.

Personal vs Enterprise: Personal uses a shared password (PSK/SAE); Enterprise uses 802.1X + EAP + a RADIUS server for per-user authentication.

1.7KRACK, and the attack WPA3 still has★ high yield

KRACK (2017)Key Reinstallation Attack. By replaying message 3 of the WPA2 4-way handshake, an attacker forces the client to reinstall an already-used key, resetting the nonce/packet counter and letting them decrypt traffic — without knowing the password. Found by Mathy Vanhoef; motivated WPA3’s SAE handshake.
Exam trapWPA3 is not flawless. Dragonblood (2019) is a class of side-channel and downgrade attacks against SAE/Dragonfly. + added The decks cover KRACK in full but never mention Dragonblood — naming it shows you know WPA3 is an improvement, not a cure.

Other wireless attacks (deck catalogue): Rogue AP, client mis-association, honeypot AP, MAC spoofing, ad-hoc/soft-AP association, and jamming (exploits 802.11’s CSMA/CA silence requirement). Countermeasures: WPA2/WPA3-Enterprise with 802.1X, SSID cloaking, disabling remote admin, and a WIPS (Wireless IPS) to detect rogue APs.

Stacks, OS, web, PKI

1.8OSI & TCP/IP — and where security livespast paper

OSI — 7 layers: Physical, Data Link, Network, Transport, Session, Presentation, Application. Wireless security operates mainly at Layer 2 (Data Link) and Layer 3 (Network). TCP/IP — 4 layers: Link, Internet, Transport, Application; encryption/authentication happen at Transport and Application.

Extra marksDraw the side-by-side mapping (added here) even if only asked to “explain the layers” — a labelled diagram earns the diagram marks the bullet list can’t.

1.9PKI, SSL/TLS, HTTPS

PKI uses asymmetric cryptography (public/private key pairs) and digital certificates issued by Certificate Authorities to prove identity — the foundation for SSL/TLS. SSL/TLS secures data in transit using those certificates; TLS 1.3 is current. HTTPS = HTTP over TLS. WPA2/WPA3-Enterprise use EAP with certificates, tying wireless auth back to PKI.

OS basics: the OS manages hardware/software/network resources; security features = user authentication, access control, host firewall; regular patching closes exploited vulnerabilities. Web basics: client–server model, browser/server/cookies, HTTP vs HTTPS.

Module 2 · Zero Trust Architecture

Perimeter security → Zero Trust

2.1Why the castle-and-moat model fails★ high yield

Perimeter (castle-and-moat) modelTraditional security treats the network as a trusted zone behind firewalls/IPS/VPN. Guards check identity once at the gateway; once inside, users are implicitly trusted and move freely.

Why it breaks: it ignores insider threats, collapses once the perimeter is breached (free lateral movement), and doesn’t fit cloud, BYOD or remote work where there is no perimeter.

Likely question“Identify the security weaknesses in the traditional perimeter-based model” — Q6a on the Feb-2026 re-paper (3 marks). Answer: implicit internal trust, single point of failure at the perimeter, no defence against lateral movement, and no fit for cloud/BYOD.

2.2“Never trust, always verify”★ high yield

Zero TrustNever automatically trust anyone or anything, inside or outside the network. Every user, device and application is continuously authenticated and authorised before accessing any resource, with least-privilege access enforced throughout.

The cycle: Authenticate → Authorise → Enforce least privilege → Monitor continuously → (repeat every session). Six components: strong identity (MFA/SSO), device compliance, least-privilege access, continuous monitoring/logging, encryption in transit & at rest, and micro-segmentation.

TraditionalZero Trust
Trust modelImplicit trust insideNever trust, always verify
BoundaryNetwork perimeterIdentity & context
AccessBroad, staticLeast-privilege, per-session
VerificationOnce, at the gatewayContinuous
ResponseReactiveProactive, automated

NIST SP 800-207

2.3The framework & its tenets★ high yieldpast paper

NIST SP 800-207 (Aug 2020)The US NIST standard framework for implementing Zero Trust in enterprises and federal agencies.

The 7 tenets (know at least five):

  1. All data sources and computing services are resources.
  2. All communication is secured regardless of network location.
  3. Access is granted per session.
  4. Access is determined by dynamic policy (identity, device, location, behaviour).
  5. The enterprise monitors the integrity and security posture of all assets.
  6. Authentication and authorisation are dynamic and strictly enforced before access.
  7. The enterprise collects as much data as possible to improve its security posture.
Likely question“Discuss the NIST SP 800-207 model — its key principles and components” is Q5 on the Feb-2026 paper (10 marks). Give the 7 tenets + the PE/PA/PEP diagram below.

2.4Logical components — PE, PA, PEP★ high yield

ComponentRole
Policy Engine (PE)Makes the allow/deny decision using the trust algorithm
Policy Administrator (PA)Executes the decision — establishes/tears down the session
Policy Enforcement Point (PEP)The gatekeeper in the data path that actually allows or denies access

Extra marksThe PE + PA together form the “policy decision point” on the control plane; the PEP is on the data plane. Drawing the control-plane / data-plane split (as above) is a distinguishing detail most students miss.

MFA, SSO & Conditional Access

2.5Multi-Factor Authentication★ high yieldpast paper

MFARequires two or more independent credentials from different categories, so compromising one factor is not enough.
FactorMeaningExample
KnowledgeSomething you knowPassword, PIN
PossessionSomething you haveOTP, smart card, phone
InherenceSomething you areFingerprint, Face ID

Security rises Knowledge → Possession → Inherence. 81% of breaches involve weak or stolen credentials (Verizon DBIR 2024) — the one-line justification for MFA in any answer.

Likely question“Explain the something-you-know / have / are principle with examples” is Q1 on the CSE337 minor paper (5 marks). This card is the whole answer.

2.6SSO, Identity Federation & Conditional Access★ high yieldpast paper

SSOSingle Sign-On — authenticate once, then reach many services without re-logging in. Scope: within one organisation. Uses session tokens.
Identity FederationExtends SSO across organisations using SAML, OAuth 2.0, OpenID Connect — e.g. logging into Zoom with your Google account, or a student reaching Coursera with university credentials.
Conditional Access Policy (CAP)Dynamic access control based on who / what / where / how — user, app sensitivity, location/IP, device compliance. Outcome per request: Allow, Deny, or step-up to MFA. E.g. login from an unknown device abroad → force MFA or block.
Extra marksReal anchors to quote: Microsoft says CAP + MFA gives 99.9% attack prevention; the 2022 Okta breach exploited SSO; the 2020 Twitter hack came from missing MFA.
Likely question“Define and differentiate IdM, Access Management and PAM with an office-building analogy” is Q5 on the CSE337 minor paper — see the IAM card below; it is not in the Zero Trust decks.

X.1IdM vs Access Management vs PAM+ addedpast paper

DisciplineQuestion it answersOffice-building analogy
Identity Management (IdM)Who are you? (lifecycle: create, update, disable accounts)The HR office that issues and revokes staff ID cards
Access Management (AM)What are you allowed into? (authentication + authorisation)The door readers that check your card at each room

Likely questionQ5 (10 marks) literally asks for these three with an office-building analogy — the table above is a full-marks answer.

X.2Active Directory & OUs+ addedpast paper

Active Directory (AD)Microsoft’s directory service for Windows domains — a central store of users, computers and resources, providing authentication and authorisation via Domain Controllers (DCs).
  • Organizational Unit (OU) — a container to group users/computers for delegated administration and to apply Group Policy Objects (GPOs).
  • Domain → Tree → Forest — the structural hierarchy; the forest is the top-level security boundary.
  • AD vs Azure AD (Entra ID) — on-premises directory vs cloud identity service for modern/hybrid apps.
  • Password management — GPO-enforced complexity, expiry, lockout and history policies.

Case studies & the compulsory Q6

X.3BYOD / remote-work scenario (the 10-mark Q6)★ high yieldpast paper

Both CSE337 papers make Section C a compulsory 10-mark case study — a university BYOD or a remote-work breach. The marking wants you to name mechanisms and say why, not describe them abstractly. A reusable answer skeleton:

  1. Risks in the current setup: shared WPA2-PSK passwords, one credential per service, no central auth, personal devices → unauthorised access, credential theft, lateral movement.
  2. Fix the Wi-Fi: WPA2-Personal → WPA3 / WPA2-Enterprise with 802.1X so each user authenticates individually.
  3. Fix identity: SSO for one secure login across ERP/LMS/email, backed by MFA.
  4. Apply Zero Trust: “never trust, always verify”, Conditional Access (block/step-up by device & location), network segmentation to contain any breach, and SDP instead of a flat VPN.
Extra marksDeck case studies worth one line each: Colonial Pipeline (2021) — one leaked VPN password, no MFA, dormant account → ransomware (MFA is not optional). Google BeyondCorp — no VPN, trust scored per device/user, ~40% fewer breaches (Zero Trust in production). Maersk / NotPetya (2017) — $300M loss → micro-segmentation limits the blast radius.
