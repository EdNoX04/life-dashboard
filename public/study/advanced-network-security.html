Man-in-the-Middle (MitM)An attacker secretly relays and possibly alters communication between two parties who believe they are talking directly to each other. It breaks confidentiality (the attacker reads everything) and integrity (the attacker can change it), and it defeats authentication because each side authenticates the attacker, not the peer.

How it happens on a wireless network: a rogue or honeypot AP, ARP spoofing, DNS spoofing, or SSL stripping (downgrading HTTPS to HTTP). Defences: mutual authentication with certificates (WPA2/3-Enterprise, TLS), certificate pinning, HSTS, and WPA3's SAE, which never exposes a crackable handshake.

3 · Malware

3.1What malware is, and how it is delivered

MalwareMalicious software that damages or disables computer systems and gives limited or full control of the system to its creator, for the purpose of theft or fraud.

Components of malware the deck names: crypter (hides the code from AV), downloader, dropper (installs the payload), exploit (the delivery vulnerability), injector, obfuscator, packer (compresses/encrypts), payload (the actual malicious action), malicious code.

Common distribution techniques: black-hat SEO (poisoning search results), malvertising, drive-by downloads, compromised legitimate websites, clickjacking, spear-phishing attachments, social-engineered links, instant-messenger applications, removable media, and browser/plug-in exploits.

Exam trapThe virus/worm distinction is the one most often lost. A virus attaches to a host and needs a user to run it; a worm is standalone and self-propagating. "A worm replicates on its own" is the deck's exact phrasing. And a Trojan does not replicate at all — calling it a virus loses the mark.

What a Trojan does: creates backdoors for remote access; steals credentials and financial data; records screenshots, audio and video; uses the host as a proxy or a bot; disables security software.

The recommendation, written outFor a modern enterprise, recommend a hybrid, weighted toward anomaly/behavioural detection. Justify it in three moves: (1) the threats that actually cause loss now — zero-days, ransomware variants, insider misuse and living-off-the-land techniques — have no prior signature, so a signature-only deployment is blind to them by construction; (2) signature detection is still worth keeping because it is cheap, fast and near-certain on the large volume of commodity attacks, and it keeps the anomaly engine from being buried in noise; (3) the practical answer is layered — signatures at the perimeter for volume, behavioural/AI analytics on endpoint and identity for the unknown. Then cite Darktrace 2024, which contained a zero-day ransomware variant in under three minutes precisely because it was behavioural.

8 · VPNs

8.1What a VPN is and how it workspast paper★ high yield

VPNA Virtual Private Network creates a secure, encrypted tunnel over a public network between a device and a remote VPN server, so that traffic crossing an untrusted network behaves as if it were on a private one.

Purpose: protects data from eavesdropping, hides the real IP address and location, and secures use of public Wi-Fi.

How a VPN works — four steps:

  1. The device initiates a connection to the VPN server and both ends authenticate.
  2. A tunnel is created using encryption protocols and session keys are negotiated.
  3. All data is encapsulated and routed through the encrypted tunnel.
  4. The VPN server decrypts and forwards traffic to its destination, and returns replies the same way.

9 · IPSec

9.1IPSec architecture and workingpast paper★ high yield

Feb 2026 Section B, 10 marks: "Describe the VPN architecture and protocols … Explain the working of IPSec and SSL/TLS in VPN." This card and the next are that answer.

IPSecA suite of protocols that secures IP communication by authenticating and encrypting each IP packet of a session. It operates at the network layer, so it protects every application above it transparently.
ComponentRole
AH — Authentication HeaderIntegrity + authentication + replay protection. No confidentiality — it does not encrypt. Protocol 51
ESP — Encapsulating Security PayloadEncryption + integrity + authentication of the payload. Protocol 50. The one actually used
IKE — Internet Key ExchangeNegotiates the algorithms and establishes shared keys (Diffie–Hellman) over UDP 500 / 4500. IKEv2 is current
SA — Security AssociationThe one-way agreed parameter set (algorithms, keys, lifetime) identified by an SPI. Two SAs are needed for two-way traffic
ModeWhat is protectedUsed for
Transport modeOnly the payload; the original IP header is keptEnd-to-end, host-to-host
Tunnel modeThe entire original packet is encrypted and wrapped in a new IP headerVPNs — site-to-site and remote access; hides the internal topology

Working, step by step:

  1. Interesting traffic matches a policy and triggers IPSec.
  2. IKE Phase 1 — the peers authenticate (pre-shared key or certificate) and build a secure, bidirectional ISAKMP SA using Diffie–Hellman. Main mode (6 messages) or aggressive mode (3).
  3. IKE Phase 2 — inside that protected channel the peers negotiate the IPSec SAs (quick mode) and derive the traffic keys.
  4. Data transfer — packets are encapsulated with ESP in tunnel mode, encrypted, authenticated and sent.
  5. Termination — SAs expire on a time or byte lifetime and are re-keyed.
Extra marksTwo facts that mark out a full answer: (a) AH breaks NAT because it authenticates the IP header that NAT rewrites, which is why real deployments use ESP with NAT-Traversal encapsulating in UDP 4500; (b) IPSec's strength — network-layer, application-transparent — is also its cost: it needs a client, gives broad network access once connected, and is exactly the "connect and you're inside" model Zero Trust and SDP replace. That sentence sets up the compulsory Section C question.

10 · SSL/TLS

10.1SSL/TLS and its role in VPNspast paper★ high yield

SSL/TLSProtocols that secure data in transit at the transport layer, using PKI certificates to authenticate the server (optionally the client) and to establish an encrypted session. TLS 1.3 is the current standard, with improved security and performance.

The handshake (TLS 1.2, the version usually examined):

  1. ClientHello — supported versions, cipher suites, client random.
  2. ServerHello — chosen cipher suite, server random.
  3. Certificate — the server's X.509 certificate, which the client validates against a trusted CA.
  4. Key exchange — (EC)DHE gives a shared pre-master secret with forward secrecy.
  5. Both derive the master secret and session keys.
  6. ChangeCipherSpec + Finished — everything after this is encrypted with symmetric keys.

TLS 1.3 cuts this to one round trip, removes RSA key transport, static DH, RC4, CBC and compression, and makes forward secrecy mandatory.

IPSec VPNSSL/TLS VPN
LayerNetwork (L3)Transport/session (L4–5)
ClientDedicated client neededClientless — a browser is often enough
Access grantedWhole networkPer-application, easier to restrict
Firewall friendlinessBlocked by some networks (ESP, UDP 500)Runs on TCP 443 — passes almost anywhere
Best forSite-to-site, full corporate accessRemote users, contractors, BYOD

Why it matters for wireless: HTTPS is HTTP over TLS. On an untrusted or attacker-controlled AP, TLS is what keeps the session confidential even when the link layer is compromised — the reason "use HTTPS on public Wi-Fi" is real advice and not folklore.

13 · WEP → WPA3

13.1WEP★ high yield

WEPWired Equivalent Privacy — a security protocol defined by 802.11b, designed to give a wireless LAN a level of security and privacy comparable to a wired LAN. It uses a 24-bit initialisation vector (IV) with the RC4 stream cipher for confidentiality and a CRC-32 checksum for integrity.

How WEP works: the WEP key is concatenated with the IV to form the WEP seed; RC4 expands the seed into a keystream; the plaintext plus its CRC-32 ICV is XORed with the keystream; the IV is sent in clear text alongside the ciphertext so the receiver can regenerate the keystream.

Why it is broken — say all four:

  1. The IV is only 24 bits, so on a busy network it repeats within hours — and a repeated IV with a static key means a reused keystream.
  2. The IV is transmitted in plaintext.
  3. RC4's key-scheduling weakness (FMS attack) leaks key bytes from enough IVs.
  4. CRC-32 is a checksum, not a MAC — it is linear, so an attacker can flip bits in the ciphertext and fix the ICV without knowing the key. No integrity at all.

Plus: no key management — the key is static and shared by everyone, forever.

13.2WPA and WPA2

WPAWi-Fi Protected Access — a security protocol defined by 802.11i that uses TKIP (Temporal Key Integrity Protocol) with the RC4 stream cipher, 128-bit keys and a 64-bit MIC integrity check. TKIP eliminates WEP's weaknesses through per-packet key mixing, message integrity checks (the Michael algorithm), extended 48-bit IVs and re-keying.
WPA2An upgrade to WPA with mandatory support for CCMP — Counter Mode with Cipher Block Chaining Message Authentication Code Protocol — an AES-based mode providing strong encryption and authentication. Defined by 802.11i.

How WPA2 works: the temporal key and a nonce built from the packet number and addresses feed AES-CCMP, which encrypts the data and produces an authenticated MIC, with additional authenticated data (AAD) covering the header.

ModeAuthenticationWhere it fits
WPA2-Personal (PSK)A set-up password — a pre-shared key — protects against unauthorised accessHomes, small offices
WPA2-EnterpriseIntegrates EAP standards with WPA2 encryption; uses RADIUS for centralised client authentication with methods such as token cards and KerberosCampuses, corporates
Exam trap"Why is WPA2-Personal not suitable for a university environment?" (Feb 2026, 3 marks). Four reasons, and the paper wants more than one: (1) one shared password for everyone — students share it, so there is no per-user identity and no accountability; (2) no revocation — removing one person's access means changing the key for the whole campus; (3) anyone who knows the PSK and captures the 4-way handshake can decrypt other users' traffic on the same network; (4) the handshake can be captured and brute-forced offline. The fix is WPA2/WPA3-Enterprise with 802.1X, giving each user their own credential via RADIUS.

13.3WPA3past paper★ high yield

WPA3A third-generation Wi-Fi security protocol and an advanced implementation of WPA2, using the AES-GCMP-256 encryption algorithm, HMAC-SHA-384 for key derivation and authentication, and ECDSA-384 for key exchange.
ModeWhat it does
WPA3-PersonalPassword-based authentication using the SAE protocol (Simultaneous Authentication of Equals), also known as the Dragonfly key exchange. Resistant to offline dictionary attacks and key-recovery attacks
WPA3-Enterprise192-bit security suite: authenticated encryption with GCMP-256, keys via HMAC-SHA-384, key exchange with ECDH and ECDSA-384

The four improvements to name:

  1. SAE replaces the PSK 4-way handshake, so there is no capturable handshake to brute-force offline — each guess costs an online interaction.
  2. Forward secrecy — traffic captured today cannot be decrypted later even if the password is discovered.
  3. OWE (Opportunistic Wireless Encryption / Enhanced Open) encrypts open hotspots, so a café network is no longer plaintext.
  4. Protected Management Frames are mandatory, which blocks deauthentication and disassociation attacks — the very step aircrack-ng relies on.

Plus DPP (Wi-Fi Easy Connect) for provisioning IoT devices with no screen or keyboard.

Extra marksBe honest about the limits — it is what separates a 10-mark answer from a 6. WPA3 is not flawless: the Dragonblood vulnerabilities (2019) found side-channel and downgrade attacks against SAE, and transition mode — where an AP offers WPA2 and WPA3 together for compatibility — lets an attacker force a client back to WPA2 and attack that instead. Mention the deck's forward look too: WPA4 is in development with quantum-resistant encryption.

15.2KRACK — Key Reinstallation Attackcase study★ high yield

KRACKAn attack that exploits the WPA2 4-way handshake by forcing nonce reuse. Discovered by Mathy Vanhoef in 2017. It works against all modern protected Wi-Fi networks and allows an attacker to steal credit-card numbers, passwords, chat messages, emails and photos.

The 4-way handshake, normally:

  1. AP → client: Message 1 — ANonce.
  2. Client → AP: Message 2 — signed SNonce.
  3. AP → client: Message 3 — signed ANonce; the client installs the encryption key.
  4. Client → AP: Message 4 — acknowledgement.

The attack: the attacker sits between the client and the AP with a cloned access point and blocks message 4. The AP, having had no acknowledgement, retransmits message 3. The client reinstalls the same key — and in doing so resets the nonce and replay counters to their initial values. Reusing a nonce with a stream cipher means the keystream repeats, so previously captured packets can be decrypted, replayed and, in some configurations, injected.

Critically: the attacker never learns the Wi-Fi password. The flaw is in the protocol's state machine, not the key strength.

Extra marksThe lessons the case-study slide draws, which is what the compulsory question rewards: (1) protocol-level flaws undermine even correctly configured encryption — implementation review matters as much as key length; (2) vendors patched by enforcing that handshake messages are processed only once; (3) KRACK directly motivated WPA3's SAE handshake, which resists this whole class of replay attack. That third point is the bridge from this card to card 13.3.

15.3Jamming and denial of service

Jamming signal attackAll wireless networks are prone to jamming. The jamming signal causes a DoS because 802.11 is a CSMA/CA protocol whose collision-avoidance algorithm requires a period of silence before a radio may transmit. An attacker with a high-gain amplifier nearby drowns out the legitimate AP.

Jamming devices (the deck lists six by model): ranges of roughly 10–150 metres, 4–8 antennas, jamming 4–8 bands simultaneously across CDMA, GSM, DCS, 3G, 4G, GPS, Wi-Fi and Bluetooth; some wall-mountable, some battery-powered for 40 minutes to 3 hours.

Related DoS on Wi-Fi: deauthentication flooding — forging deauth management frames to knock clients off, which is both a DoS and the first step of a WPA handshake capture. Protected Management Frames (802.11w), mandatory in WPA3, are the defence.

Extra marksJamming attacks availability, and it is the one goal from card 1.1 that encryption cannot protect. No cipher stops a radio being drowned out — the countermeasures are physical and operational: spectrum monitoring by a WIPS, directional antennas, frequency agility, and locating the source. Saying which security goal an attack targets is a cheap, reliable mark.

20 · Traditional perimeter security

20.1The perimeter model and the castle-and-moatpast paper★ high yield

Perimeter-based securityTraditional cybersecurity treats the organisation's network as a secure zone surrounded by protective barriers — firewalls, IPS and VPNs — and focuses on securing the outer boundary, assuming threats originate outside.

Key features:

  • Access control at the perimeter — users and devices outside are untrusted; once authenticated at the gateway, users often gain broad access within.
  • Implicit trust inside the network — devices and users inside are automatically trusted, which is a vulnerability the moment the perimeter is breached.
  • Static defence — static configurations, firewall rules and IP-based access control, with limited attention to user identity or device posture inside.
The "castle and moat" analogyThe organisation is a castle surrounded by a moat (the firewall). Guards at the gate (VPN, firewall) check identity once. Once inside, users move freely with little or no restriction.

Challenges: poor handling of insider threats; vulnerable once the perimeter is breached; ineffective for cloud services, BYOD and a remote workforce; not designed for dynamic modern environments.

21 · Zero Trust

21.1Never trust, always verifynamed in syllabus★ high yield

Zero TrustA security model whose fundamental principle is "Never Trust, Always Verify." Never automatically trust anyone or anything, inside or outside the network; every user, device and application must be continuously verified before being granted access to resources.

What the principle dictates:

  • Every user and device is continuously authenticated and authorised before access to any resource.
  • Trust is not assumed from network location or device ownership.
  • Least-privilege access is enforced — only the minimum needed for the job.
  • Constant authentication and monitoring detect and respond to threats.

Key components of a Zero Trust architecture:

24 · Authentication & MFA

24.1Multi-Factor Authenticationpast paper★ high yield

Why authentication is critical: 81% of breaches involve weak or stolen credentials (Verizon DBIR). Passwords are vulnerable to phishing, brute force and credential stuffing.

MFAAn authentication method requiring users to provide two or more independent credentials from different categories, so that compromising one factor does not give an attacker access.
CategoryPrincipleExamplesAttacked by
KnowledgeSomething you knowPassword, PIN, security questionPhishing, brute force, credential stuffing
PossessionSomething you haveOTP, smart card, mobile device, hardware tokenSIM swap, theft, OTP relay
InherenceSomething you areFingerprint, face recognition, irisSpoofing; and it cannot be reset if stolen

How MFA works: the user submits the first factor → the system validates it and challenges for a second factor from a different category → the user supplies it (approves a push, enters an OTP, presents a biometric) → the system validates and issues a session.

The Feb 2026 question, answered"What is the purpose of the 'something you know, something you have, and something you are' principle in MFA? Explain with suitable examples." The purpose is independence of compromise: the three categories fail to different attacks, so an attacker must succeed at two unrelated things at once. A phisher who steals your password (knowledge) still cannot produce your phone (possession); a thief with your phone still cannot produce your fingerprint (inherence). Two factors from the same category — a password and a security question — are not MFA, because one phishing page captures both. Then close with the number: Microsoft reports MFA blocks over 99.9% of automated account-compromise attacks.
Exam trapSay which MFA factors are weak — it is the difference between a 4-mark and a 5-mark answer. SMS OTP is vulnerable to SIM swapping and interception, and push notifications are vulnerable to MFA fatigue (spamming approvals until the user taps yes). Phishing-resistant MFA — FIDO2 security keys and passkeys — is the current recommendation because the credential is cryptographically bound to the origin.

The office-building analogy, written outIdM is the HR and pass office. How they interconnect: AM cannot decide anything without an identity IdM created, and PAM is meaningless unless the master keys are separated from the ordinary passes AM issues. Together they answer who, what and with how much power.
Extra marksAdd the governance layer: IGA (Identity Governance and Administration) is the periodic review that asks whether the access people accumulated is still justified — the answer to privilege creep, where an employee who has moved departments three times holds the permissions of all four roles. And note that PAM is where Zero Trust and IAM meet: just-in-time elevation with no standing privilege is "never trust, always verify" applied to administrators.

Why OUs exist — the three reasons to write:

Password management in identity management (the paper's other short note): policy enforcement (length, complexity, history, age, lockout), self-service password reset to cut helpdesk load, password vaulting and rotation for privileged accounts, banned-password lists checked against breach corpora, and — the modern direction — reducing reliance on passwords entirely through SSO, MFA and passkeys.

29 · Firewalls, SDP, SDN, NAC

29.1Firewalls in segmentationnamed in syllabus

Role: firewalls enforce security policy between segments, controlling traffic on source, destination, port and protocol. Traditional firewalls inspect at network and transport layers; NGFWs add application awareness, intrusion prevention and threat intelligence.

Implementation considerations: configure rules to allow only necessary traffic between segments; review and update rules as topology and requirements change; use NGFWs for visibility into application traffic and detection of advanced threats.

East-west vs north-south is the framing worth adding: perimeter firewalls filter north-south traffic (in and out of the organisation); segmentation firewalls filter east-west traffic (between internal segments) — and east-west is exactly where lateral movement happens and where traditional designs had no controls at all.

29.2Software-Defined Perimeterpast paper★ high yield

SDPA Software-Defined Perimeter creates a secure, identity-centric perimeter around applications and data, regardless of their location. Users are granted access to specific resources only after their identity and device posture have been verified. Often called a "black cloud", because unauthorised users cannot even see that the resource exists.

How it works:

  1. Authentication — the user authenticates with strong methods such as MFA.
  2. Authorisation — access is granted based on user role and device posture.
  3. Micro-segmentation — SDP creates a secure tunnel between the device and the authorised application only, effectively micro-segmenting the network.

Benefits: reduces the attack surface by hiding applications and data from unauthorised users; granular access control based on identity and device posture; simplifies network security management.

"VPN or SDP for BYOD?" (Sept 2025 Section C) — answered as a consultantRecommend SDP. Give the reasoning as a contrast, not a list. A VPN authenticates once and then places the device on the network — a personal, unmanaged laptop is granted a network address inside the perimeter, and from there it can reach anything the network routes to. That is precisely the weakness Colonial Pipeline demonstrated: one stolen VPN credential, full internal access. SDP inverts it: nothing is reachable until identity and device posture are verified, and then only the one authorised application is exposed — everything else remains invisible, so it cannot be scanned or attacked. For BYOD specifically: SDP checks device compliance at every connection, gives per-application rather than per-network access, contains a compromised student laptop to the single service it was authorised for, and needs no client VPN configuration on personal devices. Then concede the trade-offs honestly — SDP costs more, requires an identity infrastructure the university must already have, and adds a dependency on the broker's availability; a VPN is cheaper and already deployed. Conclude: keep the VPN for managed staff devices needing full network access, and put BYOD behind SDP.

29.3SDN and NACnamed in syllabus

SDNSoftware-Defined Networking separates the control plane from the data plane, allowing centralised management and automation of network resources.

Role in segmentation: SDN can dynamically create and manage segments as security requirements change. Benefits: centralised control and visibility; automated provisioning and configuration; dynamic segmentation driven by real-time security events. Considerations: choose a controller supporting the segmentation features you need; integrate with security tools to automate response; and protect the controller itself — it is a single point of total compromise.

NACNetwork Access Control governs access to the network based on user identity, device posture and security policies, and can automatically assign users and devices to appropriate segments.

How NAC works: authentication of users and devices before network access → posture assessment (up-to-date antivirus, OS patches, disk encryption) → policy enforcement, placing the device in the right segment or a remediation VLAN. Benefits: only authorised, compliant devices connect; non-compliant devices are kept away from sensitive resources; segmentation is automated by role and posture.

Extra marksShow how the four technologies compose rather than compete: NAC decides whether a device may join and which segment it lands in; SDN builds and rewires those segments programmatically; firewalls enforce policy between them; SDP removes the network step entirely by connecting an identity straight to an application. That sentence answers "using firewalls, SDN and NAC" as one coherent architecture, which is what the descriptor is asking for.

On the CAPTCHA questionIt is the one question with no deck slide behind it, so build the answer from first principles. CAPTCHA separates humans from automated clients, so it filters the bot-generated request floods that make up an application-layer (Layer 7) DDoS while letting real users through — unlike rate limiting, which penalises everyone. It complements IDS/IPS because an IDS/IPS decides from traffic patterns and signatures and struggles when each individual request looks legitimate; CAPTCHA adds a challenge–response test the traffic itself cannot answer. The practical arrangement: the IDS/IPS detects the anomaly and triggers CAPTCHA only for suspicious sources, so protection escalates rather than blocking indiscriminately. Limits, for the last mark: CAPTCHA does nothing against volumetric Layer 3/4 floods that saturate the link before any application logic runs, it can be solved by farms and by ML, and it harms accessibility — which is why invisible reputation-based challenges have largely replaced it.

Exam trap — final checklist
